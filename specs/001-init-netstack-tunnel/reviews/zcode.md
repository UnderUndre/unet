## Summary

The post-surgery `001-init-netstack-tunnel` package is much cleaner after relocating `FR-011`/`FR-012` to `003-ecosystem-integration` and adding `T3a` for the gateway side, and the anti-DNS-leak / permission-hardening intent is strong. However, checking the specs and JSON schema line-by-line against the actual `amneziawg-go` + `tun/netstack` codebase in `repos/unet` surfaces **three implementation-blocking CRITICAL gaps**: `TunnelConfig` omits the client's tunnel IP addresses (`local_addresses`) under `additionalProperties: false`, `resolution_mode: "remote"` assumes a hostname-forwarding exit protocol that does not exist over raw WireGuard L3, and the `yamux` stream framing / gateway listener topology / multi-tenant port routing in `contracts/interfaces.md` contradict themselves. On top of that, `ObfuscationParams` in `config.schema.json` clashes with AWG 1.5 UAPI validation in `device/uapi.go` and `device/magic-header.go`.

| F2 | CRITICAL | Architecture / Security (DNS) | `resolution_mode: "remote"` (`spec.md:92-93`, `research.md:110`, `contracts/interfaces.md:18-20`, `data-model.md:26`) is framed as forwarding SOCKS5 `ATYP=0x03` / HTTP hostnames "to the remote exit for resolution" with `dns` allowed to be empty. AmneziaWG/WireGuard is an L3 IP tunnel (`tun/netstack/tun.go` reads/injects raw IP packets only) with no hostname-forwarding protocol; neither `ops/option0-baseline/server-install.sh`, `contracts/interfaces.md`, nor `tasks.md` (`T3a`) defines an exit-side SOCKS5/resolver daemon, and `tun/netstack/tun.go:494-760` (`LookupContextHost`) only resolves via `dnsServers` over port 53 inside the tunnel. | Either remove `"remote"` mode in v1 and require `tunnel_dns` with at least one tunnel-reachable resolver IP (e.g. `10.66.0.1` or `1.1.1.1` routed via `allowed_ips`), or explicitly specify and task the exit-side proxy/DNS-forwarding protocol in `contracts/interfaces.md` and `T3a`/VPS setup. |
| F3 | CRITICAL | Wire Protocol / Gateway Topology | Three defects block interoperable `T3` ↔ `T3a` implementation in `contracts/interfaces.md`: (1) **Undefined stream framing** (`interfaces.md:52-75`): `open` JSON is described as arriving on each inbound open-stream request, yet `hashicorp/yamux` `OpenStream()` carries no application payload in its SYN frame — without a length-prefix or newline + ack rule separating the JSON control header from raw TCP payload bytes, `json.Decoder` read-ahead consumes the first bytes of the proxied TCP stream; (2) **Broken listener topology** (`interfaces.md:113-117`): §4 says the gateway "binds loopback only (`127.0.0.1:9443`)", which is unreachable from `unet` dialing `gateway.address` *inside* the `awg0` tunnel (`10.66.0.1:7000`), mixes public Caddy traffic with `POST /v1/gateway/revoke` unless separated, and omits how `T3a` removes peers from `amneziawg-go` (`device/uapi.go:534` `remove=true` vs embedded `Device`); (3) **Multi-tenant collision & untrusted allow-list** (`interfaces.md:96-132`): §4.3 routes by `(public_port, proto)` and rejects >1 matching session with `403`, so two clients exposing `public_port: 443` under different hostnames collide immediately, while `hello` (§2.1) does not carry `allow_list` and `PortMapping` has no `proto`. | Specify exact wire framing (e.g., 2-byte length-prefixed JSON on a dedicated control stream or newline-delimited header + ack before byte relay on data streams); split gateway listeners cleanly (Caddy ingress on loopback, `yamux` TCP listener on `awg0` tunnel IP, isolated admin/revoke endpoint wired to `amneziawg-go` UAPI); and route by gateway-configured `(public_host, public_port)` → `client_public_key` rather than client-asserted `allow_list` matching alone. |
| F4 | HIGH | Codebase / Schema Compatibility | `ObfuscationParams` (`contracts/config.schema.json:54-69`, `data-model.md:38-40`) conflicts with `repos/unet` AWG 1.5 (`device/uapi.go:310-448`, `device/magic-header.go:17-46`, `README.md:73-108`): (1) `device/uapi.go:315,327,339` rejects `jc <= 0`, `jmin <= 0`, `jmax <= 0`, whereas the schema sets `"minimum": 0` and marks them required without requiring `jmin <= jmax` or omitting zero values on UAPI write; (2) `device/magic-header.go:17-46` supports `"min-max"` range strings for `H1-H4`, whereas schema locks `h1..h4` to `"type": "integer"` with no `uint32` bounds (`0..4294967295`); (3) `s3`, `s4`, and `i1..i5` (supported in `device/uapi.go:365-448` and commit `1cc9427`) are omitted and blocked by `additionalProperties: false`. | Update `ObfuscationParams` in `config.schema.json` and `data-model.md` to allow `uint32` (`0..4294967295`) or `"min-max"` range strings for `h1..h4` (enforcing pairwise distinctness), add optional `s3`, `s4`, `i1..i5`, validate `jmin <= jmax`, and document omitting `jc/jmin/jmax` from UAPI when `jc == 0`. |
| F5 | HIGH | Security / Auth & Replay | `POST /v1/gateway/revoke` (`contracts/interfaces.md:134-139`, `spec.md:80`) defines `sig = hmac-sha256(pubkey \|\| issued_at, shared_secret)` without: (1) canonical field delimiter/encoding (`issued_at` ASCII vs big-endian binary, hex vs base64 `sig`), (2) an `issued_at` freshness/skew window to block indefinite replay of captured revoke requests, or (3) durable persistence of the revocation list so a gateway restart does not un-revoke peers. | Specify canonical HMAC input (e.g. `pubkey + "\n" + strconv.FormatInt(issuedAt, 10)`), reject requests outside a bounded skew window (e.g. `±5m`), persist revoked pubkeys on disk (or sync from authoritative store on startup), and ensure `401` audit logs never print `sig` or the secret. |
| F6 | HIGH | Security / HTTP Proxy | `interfaces.md:9,36-42` multiplexes SOCKS5 and HTTP on `127.0.0.1:1080` and supports `CONNECT`, absolute-form, and origin-form HTTP requests, but: (1) plain HTTP forwarding omits stripping hop-by-hop headers — notably `Proxy-Authorization`, which would leak the local proxy password (`FR-004`) to upstream HTTP origins; (2) first-byte protocol demuxing (`0x05` vs HTTP methods) and malformed-preamble handling are undocumented; (3) `config.schema.json:97-105` permits `auth_enabled: true` with empty `username`/`password`/`password_env`. | Mandate stripping `Proxy-Authorization`, `Proxy-Connection`, `Connection`, `TE`, `Upgrade` (and handling multi-request keep-alive target switches) in `interfaces.md` §1.4; document the port-1080 demux behavior; and add schema/loader validation requiring non-empty credentials when `auth_enabled: true`. |

## Alternative approaches considered

- **In-tunnel DNS without an exit daemon (F2)**: Instead of inventing a custom exit-side hostname-forwarding protocol for `resolution_mode: "remote"` over L3 WireGuard, v1 can simply use `tunnel_dns` pointing to a lightweight DNS resolver (e.g., `dnsmasq` / `unbound` / `coredns`) bound to the VPS tunnel IP (`10.66.0.1:53` in `ops/option0-baseline`), which `tun/netstack` already supports natively via `Net.LookupContextHost`.
- **Gateway-managed reverse routes via Caddy + static peer config (F3)**: Rather than dynamically learning `allow_list` from client `yamux` `hello` frames or routing solely by `(public_port, proto)`, keep the authoritative `(public_host, public_port) → client_public_key` table on the gateway (matching §2.4) while the client still enforces its local `gateway.allow_list` as defense-in-depth.
